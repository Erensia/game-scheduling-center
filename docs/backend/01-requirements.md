# 01. 요구사항 정의서 (기획안)

> 이 문서는 지금의 정적 프론트엔드(파밍 관제소)가 로컬에 저장하며 제공하고 있는 기능을,
> Spring Boot 백엔드가 대체/지원해야 할 요구사항으로 정리한 것이다.
> 새 기능을 추가하는 문서가 아니라, **현재 동작을 스펙으로 고정**하는 것이 1차 목표다.

## 1. 배경 및 목적

- 현재 버전은 게임 캐릭터 육성/주간 컨텐츠 관리 데이터를 브라우저의 `localStorage`에만 저장한다.
- 기기를 바꾸거나 브라우저 데이터가 삭제되면 데이터가 유실되며, 여러 기기 간 동기화가 불가능하다.
- Spring Boot 기반 REST API 백엔드를 구축해 데이터를 서버(DB)에 영속화하고,
  프론트엔드는 UI/렌더링 로직을 그대로 유지한 채 데이터 계층만 API 호출로 교체한다.

## 2. 범위 (MVP 기준)

### 포함 (MVP)
- 게임(Game) 등록/조회/수정/삭제
- 캐릭터(Character) 등록/조회/수정(완료 토글 포함)/삭제
- 캐릭터별 육성 체크리스트 항목(Checklist Item) 추가/토글/삭제
- 주간 컨텐츠(Weekly Content) 등록/조회/완료 토글/삭제, 게임별 리셋 요일 설정
- 캐릭터 육성 템플릿(Template) 저장/조회/삭제, 캐릭터 생성 시 템플릿 적용
- 파티(Party) 구성 — 파티 생성/이름 변경/슬롯에 캐릭터 배정/삭제
- 기존 백업 JSON(localStorage 내보내기 파일) 가져오기(마이그레이션용, 1회성 기능으로 우선 고려)

### 제외 (MVP 이후로 미룸)
- 로그인/회원가입, 사용자별 데이터 분리 (1인 개인용으로 우선 개발 — 인증은 2단계 목표)
- 실시간 동기화(웹소켓 등)
- 여러 사용자 간 데이터 공유/열람

## 3. 기능 요구사항 (현재 프론트엔드 기준)

| ID | 기능 | 설명 |
|---|---|---|
| FR-1 | 게임 CRUD | 이름, 주간 리셋 요일(0~6)을 가진 게임을 생성/조회/수정/삭제 |
| FR-2 | 캐릭터 CRUD | 게임에 속한 캐릭터 생성/조회/삭제, 완료 여부(`completed`) 토글 |
| FR-3 | 체크리스트 항목 CRUD | 캐릭터에 속한 자유 텍스트 항목 추가/완료 토글/삭제 |
| FR-4 | 주간 컨텐츠 CRUD | 게임에 속한 주간 컨텐츠 항목 추가/삭제, 완료 토글 |
| FR-5 | 주간 리셋 로직 | 게임별 리셋 요일 기준으로 "이번 주" 완료 여부를 계산 (리셋 요일이 지나면 자동으로 미완료로 표시) |
| FR-6 | 템플릿 CRUD | 캐릭터의 체크리스트 구성을 이름 붙여 게임 단위로 저장, 목록 조회, 삭제 |
| FR-7 | 템플릿 적용 | 캐릭터 생성 시 템플릿을 선택하면 체크리스트 항목이 그대로 복사되어 생성 |
| FR-8 | 파티 CRUD | 게임에 속한 파티 생성/이름 변경/삭제, 슬롯별 캐릭터 배정(빈 슬롯 허용) |
| FR-9 | 홈 대시보드 집계 | 전체 게임을 가로질러 미완료 주간 컨텐츠 목록, 육성 필요 캐릭터 목록을 게임별로 그룹핑해 반환 |
| FR-10 | 데이터 가져오기/내보내기 | 기존 localStorage 백업 JSON 구조를 그대로 가져와 초기 데이터로 이관 |

## 4. 비기능 요구사항 (초안 — 06-tech-stack.md에서 구체화)

- 개인용 포트폴리오/실사용 목적으로, 대규모 트래픽을 고려하지 않는다.
- 응답 지연보다 코드 구조(계층 분리, 테스트 가능성)의 명확성을 우선한다.
- 프론트엔드는 그대로 유지하고, API 계약(명세서)이 바뀌면 프론트엔드 수정 범위를 최소화할 수 있도록 설계한다.
